
背景介绍：

这是一个 AI Agent，里面有两个大模型，一个是通用大模型（只接收文本输入），一个视觉大模型（接收文本输入和图片输入，专门用于图片识别）。

这个AI agent 会把文本内容发给 通用大模型回答，把图片内容发给视觉大模型回答。
注意一点的是，AI agent 会把视觉大模型的回答，再加上一条消息 "遇到这种场景，机器人指令是什么？" 发给通用大模型。

## 六足机器人指令 JSON 协议

指令的 desc 作为描述。六足机器人驱动程序可以执行以下指令：

### 语音播报 speak 指令 

字段规定：task 属性规定是 speak，text 属性是一段文本，这段文本将会转为语音，在机器人喇叭播报。

`{"desc": "播放", "task": "speak", "text": "(播报内容)"}`

例如：`{"desc": "报警", "task": "speak", "text": "报警"}`
### 行走 nav 指令 

字段规定：task属性规定是 nav，position 属性是一个 json 对象，里面有 x，y， z， orientation 属性是一个 json 对象，里面有 x，y，z。 position 属性和 orientation 属性的数值可以通过机器人的具体行走坐标得到。

`{"desc": "走到某个点", "task": "nav", "position": {"x": （坐标数值）, "y": -1.62110, "z": 0.0}, "orientation": {"x": 0.0, "y": 0.0, "z": 0.71291, "w": 0.701248}}`。 

例如：  `{"desc": "走到左上角", "task": "nav", "position": {"x": 1.136546, "y": -1.62110, "z": 0.0}, "orientation": {"x": 0.0, "y": 0.0, "z": 0.71291, "w": 0.701248}}`

由于坐标信息比较多，六足机器人驱动程序 `vkhex.py` 可以从 配置文件中 读取 具体的 nav 指令坐标。

比如指令 `{"desc": "走到左上角", "task": "nav"}` , 
而配置文件中已经有相关配置，例如 

```json
{
	"tasks": [
	{
		"desc": "走到左上角",
		"task": "nav",
		"position": { "x": 2.48045992851, "y": -0.119409501553, "z": 0.0 },
		"orientation": { "x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0 }
	}
	]
}
```

那么 大模型接口在回答的时候，可以省去 position 属性和 orientation 属性， 驱动程序 `vkhex.py` 会自动从配置文件中找到对应的 position 属性和 orientation 属性。


## 六足机器人工作流程：

- 第一轮提问：向大模型提问行走路线的指令，并且提问中包含遇到场景的解决方案。得到行走nav指令列表 后，开始按顺序执行 nav 指令。
- 第2轮到第N轮提问：每隔一段时间向大模型发送拍照得到的图片，大模型识别出异常场景，返回遇到该异常场景的解决方案的指令列表。机器人会优先执行这些指令列表，优先级比行走 nav 指令高。
- 最后一轮提问：向大模型提问工作汇报。大模型把一路上遇到的异常场景汇总，返回语音播放指令。

## 大模型 AI agent 要求

- 有路线规划能力，能把一个路线分解为多个机器人指令。具有记忆多个场景的解决方案的能力
- 遇到场景，能回答该场景下的指令。

## 大模型 AI agent 回答要求和示例

回答格式要求是 json 格式，是上面提到的 机器人指令 json 列表。

- 第一轮提问：巡检任务是走一圈，机器人起始位置是右下角。机器人指令是什么？指令分解为 `[{"desc": "走到左下角", "task": "nav"}, {"desc": "走到左上角", "task": "nav"}, {"desc": "走到右上角", "task": "nav"}, {"desc": "走到右下角", "task": "nav"}]`

## 为了完成这个 AI agent，有两个任务

- 给定一个视觉大模型和一个参数比较大的通用大模型，编写系统提示词，让 AI agent 的回答符合要求。
- 给定一个参数比较小的通用大模型，编写系统提示词，制作数据集，对这个参数比较小的通用大模型进行微调训练， 让通用大模型 对于文本的回答符合要求。
